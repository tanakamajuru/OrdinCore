Data Security at Ordin Core

Last updated: 3 November 2026

Ordin Core is built to hold sensitive care-governance records for regulated health and social care providers. Security is treated as a first-class requirement, not an afterthought — enforced in the application layer, the database, and the infrastructure it runs on.

Tenant isolation

Every organisation's data is isolated from every other organisation's at the database layer. Requests are authenticated, scoped to the calling organisation, and role-checked before any record is returned.

Authentication & access control

  • Passwords are hashed (never stored or logged in plain text) and expire periodically.
  • Access is role-based: staff only see the services and records they are assigned to.
  • Login and other sensitive routes are rate-limited against brute-force attempts.

Encryption

Data in transit is protected with TLS. Backups are encrypted. Evidence media (photos, voice notes) is only reachable through authenticated, access-logged requests.

Audit logging

Security-relevant actions — logins, record changes, review sign-offs — are written to an audit log with who, what and when, supporting incident investigation and regulatory evidence requests.

Backups & continuity

Data is backed up on a regular automated schedule and restore-tested, with ongoing work to keep an independent, off-server copy.

Secure development

Secrets are never committed to source control and are scanned for automatically. Dependencies are checked for known vulnerabilities, and changes go through automated build and test checks before release.

Ongoing assurance

We run internal security testing against the application and act on findings. Further independent certification work is in progress.
